Foundations: The System Behind This Site

This site runs on a small, deliberate token layer rather than a pile of one-off values. This page documents it — and audits it against the public Design System Checklist ↗, including the parts that failed and what I did about them.

Why publish this

A portfolio usually shows the output and hides the method. This page shows the method. I ran my own site through an external standard, measured it, found real defects, fixed them, and left the remainder visible instead of quietly tidying it away.

That is the job I want to be doing: not producing screens, but deciding what "good" means, making it measurable, and holding the work to it — including when the work is mine.

Principles

Four rules that decide the arguments before they start.

  • Evidence over aesthetics A choice I can defend with a reason beats one I can only defend with taste. Contrast ratios, not "it looks fine to me."
  • Accessible by default, not by request Keyboard access, focus order and contrast are part of the definition of done — not a pass someone does later, and not a feature a client has to ask for.
  • Ship it, then keep it honest A system that exists and is 77% adopted beats a perfect one in a slide deck. Measure the gap and publish it.
  • Decisions get written down Every token here encodes a decision someone would otherwise have to re-litigate. Z-index layers are named so "what sits above what" is recorded, not rediscovered.

Color

Eleven tokens: a neutral base, one accent, and four semantic colors. Every value used as text clears WCAG AA (4.5:1) against all three surfaces — --bg, --bg-card and --white.

The audit caught three failures here. --text-muted and --accent were nudged until they passed. The interesting one was --success: the mint green reads at 1.74:1 as text — effectively unreadable — but it works as a 6px status dot, where the bar is 3:1 for non-text UI. One value could not do both jobs, so it became two.

Spacing

Sixteen steps, derived from the values the site was already using rather than imposed on top of them — so adopting the scale moved nothing. 125 of 162 spacing declarations (77%) sit on it exactly, at zero pixel drift, verified by diffing the geometry of 442 elements before and after.

Typography

Three families, all SIL OFL licensed: Syne for display, DM Sans for body, DM Mono for labels and metadata. Loaded with preconnect and display=swap, each with a real system fallback, so text is never invisible while fonts download.

Display sizes are fluid — clamp() across six headline scales — so type responds to the viewport continuously instead of jumping at breakpoints. Below display size the scale is not yet tokenized; see open work.

Elevation & layering

Motion

Two easing curves and three durations — --dur-fast 0.25s, --dur-base 0.4s, --dur-slow 0.6s — so transitions feel like one hand made them.

Every one of them collapses to ~0 under prefers-reduced-motion. The audit found this was only a third wired: three JavaScript features checked the preference, but seven infinite CSS animations — the pulsing avatar badge, scanlines, flicker — ignored it entirely. That is now a global rule, with one explicit exception: the hero scroll indicator animates to scaleY(0), so freezing it at its final frame would have made it vanish.

Accessibility

The commitments this site actually keeps, not the ones it aspires to.

  • Every text color clears AA 4.5:1 minimum against all three surfaces, measured rather than eyeballed.
  • A skip link opens the tab order WCAG 2.4.1. One Tab and Enter bypasses the nav on every page.
  • Collapsed panels are inert A closed Q&A panel clips to zero height but used to keep its video focusable — 20 invisible tab stops. Closed panels are now removed from the tab order and the accessibility tree entirely.
  • Keyboard focus reveals what it reaches Focusing a question opens it; focusing a workflow dot shows its step and holds the carousel. You can see where you are before you commit.
  • Motion is a preference, not a default All animation respects prefers-reduced-motion.
  • Decorative images say nothing All seven inline SVG icons carry aria-hidden, so screen readers aren't read decoration.

Open work

What the audit found that is still outstanding. Listing it is the point: a system you can't name the gaps in isn't being managed, it's being hoped over.

  • No dark mode Zero prefers-color-scheme queries. The elevation tokens are already written to swap shadow for surface color when it lands.
  • Type scale not tokenized 46 distinct font sizes below display size. Needs a scale and a design pass, since snapping changes how the page reads.
  • 37 spacing declarations off-scale Values like 2.75rem and 1.1rem. Each needs a judgement call, not a find-and-replace.
  • Elevation tokens defined but unadopted Seven hand-written shadows remain. Consolidating them to three changes how surfaces read, so it's a design decision rather than a refactor.
  • ~12 ad-hoc breakpoints 768, 760, 700, 680, 640, 620. Should collapse to a defined set.

Method

Contrast ratios were computed from the token values using the WCAG relative-luminance formula, not sampled by eye. The spacing migration was verified by capturing width, height and document-absolute position for all 442 elements on the homepage before and after, then diffing: one element differed, and it was the rotating headline, which changes width as the phrase changes.
